<threat_model>

## Trust Boundaries

| Boundary                                   | Description                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------- |
| Browser → /api/tasks, /api/inventory, etc. | Authenticated requests; householdId comes from JWT, NOT from request body |
| Admin-only operations                      | Role check from event.context.user.role; client cannot elevate own role   |

## STRIDE Threat Register

| Threat ID | Category               | Component                                 | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                                                                                                       |
| --------- | ---------------------- | ----------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-03-01   | Information Disclosure | All GET data routes                       | mitigate    | householdId ALWAYS sourced from event.context.user (set by JWT middleware), never from query params or body — prevents cross-household data reads                                                                                                                                                                                                                                     |
| T-03-02   | Tampering              | PATCH/DELETE data routes                  | mitigate    | All update/delete queries include { \_id: id, householdId } in filter — a user cannot modify another household's documents even with a valid JWT                                                                                                                                                                                                                                      |
| T-03-03   | Tampering              | members.post.ts — invite creation         | mitigate    | Admin-only guard (callerRole !== 'admin' → 403); householdId from JWT context, not body                                                                                                                                                                                                                                                                                               |
| T-03-04   | Tampering              | members.delete.ts — self-deletion         | mitigate    | Explicit check: id === userId → 400; prevents admin from locking themselves out                                                                                                                                                                                                                                                                                                       |
| T-03-05   | Tampering              | household.patch.ts — rename by non-owner  | mitigate    | householdId sourced from JWT; user can only rename their own household; no ownership escalation possible                                                                                                                                                                                                                                                                              |
| T-03-06   | Tampering              | POST body supplies householdId            | mitigate    | All POST handlers spread body AFTER setting householdId from context: { householdId, ...body } — if body contains householdId, Mongoose schema accepts the context value first (or the spread overwrites with attacker value). SAFER: explicitly exclude householdId from body spread. Executor must NOT include householdId in the body spread — set it separately from context only |
| T-03-07   | Spoofing               | NoSQL injection via operator keys in body | mitigate    | Mongoose schema typed fields reject operator objects ($where, $gt, etc.) as type errors; avoid passing raw body objects directly as query operators                                                                                                                                                                                                                                   |

</threat_model>
