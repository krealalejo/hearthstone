<threat_model>

## Trust Boundaries

| Boundary                      | Description                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------ |
| Browser Pinia store → /api/\* | $fetch calls carry httpOnly cookie automatically; store never holds JWT string |
| app/middleware/auth.ts        | Client-side UX redirect only; server middleware is the authoritative guard     |
| auth.vue form → /api/auth/\*  | User-supplied credentials; error messages must not reveal whether email exists |

## STRIDE Threat Register

| Threat ID | Category               | Component                                           | Disposition | Mitigation Plan                                                                                                                                                                                       |
| --------- | ---------------------- | --------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-04-01   | Information Disclosure | auth.vue error display                              | mitigate    | Display server statusMessage (e.g., 'Invalid credentials') — the server already uses the same message for unknown email and wrong password, so no additional enumeration risk from client display     |
| T-04-02   | Tampering              | Pinia store state manipulation via browser devtools | accept      | Pinia state is client-only display cache; all writes go through $fetch to authenticated API routes; server validates householdId from JWT — devtools state tampering cannot bypass server checks      |
| T-04-03   | Elevation of Privilege | app/middleware/auth.ts bypass                       | accept      | Client middleware is UX-only redirect; server/middleware/auth.ts is the authoritative gate — a user bypassing the Nuxt client middleware still hits 401 on every API call                             |
| T-04-04   | Tampering              | useAsyncData key collision across pages             | mitigate    | Each useAsyncData call uses a unique key string ('tasks', 'inventory', 'shopping', 'history', 'household', 'members', 'current-user') — Nuxt deduplicates by key, so no cross-page data contamination |
| T-04-05   | Denial of Service      | Optimistic update storm on rapid UI actions         | accept      | Standard optimistic pattern; each action fires one $fetch; no debouncing in Phase 1 — acceptable for household-scale usage; flag for Phase 2                                                          |

</threat_model>
